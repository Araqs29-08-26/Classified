## Главное правило: черновик и боевой сайт — разные вещи

Работа идёт в ветке `main` — это **черновик**. Он собирается автоматически и виден
по адресу черновика. Боевой сайт живёт в ветке `production` и **сам не обновляется**.

Пока правку не выкатили, на araqs.com её нет — сколько бы её ни правили в черновике.

**Выкатка на боевой сайт** — одна команда:

```bash
git -C C:/Projects/Classified push origin main:production
```

Через минуту-полторы Vercel соберёт сайт, и правки появятся на araqs.com.

**Откат, если что-то сломалось.** Откройте [список деплоев](https://vercel.com/araqs/classified/deployments),
найдите последний, где сайт работал, → «⋯» → «Promote». Занимает секунды.

⚠️ **После отката** новые сборки перестают попадать на домен сами: Vercel запоминает,
что вы закрепили старую версию. Чтобы вернуться к нормальному ходу, нужно так же
вручную нажать «Promote» на новой сборке.

## Как менять тексты на сайте

Все тексты лежат в трёх файлах, по одному на язык:

```
messages/ru.json   русский
messages/hy.json   армянский
messages/en.json   английский
```

Правило одно: **меняете текст — меняйте во всех трёх файлах**. Ключ слева трогать
нельзя, меняется только строка справа от двоеточия.

```json
"button": "Связаться",          ← правильно: меняем «Связаться»
"кнопка": "Связаться",          ← неправильно: ключ менять нельзя
```

Что нельзя ломать:
- **кавычки и запятые** — файл перестанет читаться, и сайт не соберётся;
- **подстановки в фигурных скобках** — `{count}`, `{operator}`, `{digit}`. Это места,
  куда сайт вставляет числа и названия. Если убрать — вместо числа будет пусто.

После правки текстов сайт нужно выкатить (команда выше).

## ⚠️ Задача, которая ждёт: вычитка армянского

**Это самое срочное из того, что здесь написано.**

В файле `messages/hy.json` есть раздел `engine` — 51 строка. Это описания узоров
номера, пояснения и объяснения сборов: «зеркальный участок из 6 цифр», «Viva:
номер в пользовании 40 месяцев…» и подобные.

Эти строки **перевёл на армянский Claude, не носитель языка**. Смысл и подстановки
выверены, но окончания, порядок слов и естественность звучания нужно проверить
живому человеку.

**Что сделать:** дать раздел `engine` из `messages/hy.json` на вычитку человеку,
свободно владеющему армянским, и внести его правки. Кода это не касается вовсе —
только строки справа.

Заодно стоит проверить и остальные армянские тексты в том же файле: часть из них
тоже написана не носителем.

## Объявления

### Скрыть объявление

Панель Supabase → **Table Editor** → таблица `listings` → найти строку → поле
`listing_status` → поменять `active` на `hidden` → сохранить.

Объявление сразу пропадает с сайта, его страница начинает отдавать «не найдено».
Запись при этом цела.

Возможные значения: `active` (видно), `hidden` (скрыто), `reserved` (забронировано),
`sold` (продано).

**Удалять объявления не нужно.** Скрытие делает то же самое, но обратимо.

### Вернуть скрытое

Тем же способом: `hidden` → `active`.

### Что нельзя править руками

Поля `beauty_index`, `pattern_code`, `pattern_params`, `engine_version`,
`evaluated_at` — это оценка движка на момент публикации. Она специально
зафиксирована: движок будет меняться, а объявление должно помнить, чем и когда
его оценили. Если поправить руками, оценка на карточке разойдётся с реальностью.

## Жалобы на объявления

Посетители жалуются кнопкой «Пожаловаться» внизу карточки объявления. Жалобы
попадают в таблицу `reports`.

**Читать их можно только в панели Supabase** — на сайте они не показываются нигде
и никому. Это сделано намеренно.

Панель Supabase → **Table Editor** → таблица `reports`.

| Поле | Что означает |
|---|---|
| `listing_id` | На какое объявление пожаловались |
| `reason` | Причина — код, см. таблицу ниже |
| `reporter_id` | Кто пожаловался. Пусто — жаловался не вошедший посетитель |
| `status` | `new` (новая), `reviewing` (разбираем), `resolved` (решена), `dismissed` (отклонена) |
| `created_at` | Когда пожаловались |

Коды причин:

| Код | Причина |
|---|---|
| `not_owner` | Номер не принадлежит продавцу |
| `fraud` | Мошенничество или обман |
| `wrong_data` | Неверные данные: цена, статус или оператор |
| `spam` | Спам или оскорбительное содержание |

**Порядок работы:** разобрали жалобу — поменяйте `status` с `new` на `resolved`
или `dismissed`, чтобы она не висела в очереди.

⚠️ **Ограничение, о котором стоит помнить:** жалобу может подать кто угодно и
сколько угодно раз, ограничений нет. Пока площадка маленькая — не проблема.
Когда пойдёт поток, понадобится защита от накрутки; это отдельная задача.

## Телефоны продавцов

Телефон покупатель видит только после нажатия «Связаться». До нажатия его нет
ни в странице, ни в её исходном коде — поисковики и сборщики его не соберут.

В базе телефоны лежат в таблице `profiles`, поле `phone`. **Читать их списком
через сайт нельзя** — доступ закрыт правилами базы. Функция отдаёт телефон
по одному объявлению за раз и только для активного.

Полностью закрыть телефоны можно будет только после введения входа по email —
тогда их увидят лишь вошедшие. Это отдельная задача из очереди работ.

## Оценка номеров

Считает движок — файл `src/lib/araqs-number-engine.js`. Его пишет и обновляет
разработчик движка; править этот файл руками не нужно.

**Проверка после обновления движка.** Две команды в папке `C:\Projects\Classified`:

```bash
npm run test:engine
```

Показательные случаи, читаются человеком: 15 номеров с ожидаемыми статусами.

```bash
npm run test:control
```

Полная сверка: 385 реальных номеров рынка со всеми числами — статус, индекс,
диапазон цены, сбор за переоформление. Должно быть «Всё сошлось».

Если после новой версии движка сверка не сходится — **не выкатывать**, а вернуть
файл разработчику с текстом ошибки.

## Что сломает сайт — не делайте этого

| Действие | Что будет |
|---|---|
| Убрать запятую или кавычку в `messages/*.json` | Сайт не соберётся |
| Удалить `{count}` и подобное из текста | Вместо числа будет пусто |
| Менять Framework Preset в настройках Vercel | Сайт отдаст «не найдено» на всех страницах |
| Нажать «Disconnect» в Settings → Git | Отвалится автоматическая сборка |
| Менять правила доступа в Supabase | Могут перестать работать телефоны или объявления |
| Править `beauty_index` и соседние поля руками | Оценка на карточке разойдётся с реальностью |

## Что делать, если сайт лёг

1. Проверьте, открывается ли araqs.com. Если «не найдено» на всех страницах —
   почти наверняка дело в последней выкатке.
2. Откройте [список деплоев](https://vercel.com/araqs/classified/deployments).
3. Найдите последнюю сборку, где сайт работал (обычно предыдущая по времени).
4. «⋯» → «Promote». Сайт вернётся за секунды.
5. Потом уже разбирайтесь, что было не так в новой сборке.

Откат ничего не ломает и не теряет — это просто переключение домена на другую
готовую сборку.
