# Серверные функции Supabase

Здесь лежат исходники трёх функций, которые работают внутри Supabase, а не
на сайте. Каждая делает одно: отправляет письмо.

| Папка | Кому пишет | Когда |
|---|---|---|
| `notify-support` | администратору | человек написал через форму «?» в углу сайта |
| `notify-report` | администратору | посетитель пожаловался на объявление |
| `notify-seller` | продавцу | покупатель написал письмо по объявлению |

## Зачем копия здесь, если они уже развёрнуты

**Ежедневные резервные копии Supabase их не спасают.** Копии снимаются с базы
данных, а код функций в базе не лежит — он хранится отдельно. Пропадёт проект
— пропадут и функции, а восстанавливать почту с нуля мы уже пробовали: на это
ушло четыре попытки и полдня.

Поэтому исходник живёт в Git рядом с сайтом. Это единственная копия, которая
не зависит от Supabase.

**Правило: правим здесь, потом разворачиваем.** Если поправить функцию только
в панели Supabase, копия в Git молча устареет — и однажды восстановится не то,
что работало.

## Что в копию не входит и почему

Четыре значения почты — `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS` —
и адрес поддержки `SUPPORT_TO` хранятся в
**Supabase → Edge Functions → Secrets**. В Git их нет и быть не должно: пароль
от почтового ящика в открытом хранилище кода — это пароль, который рано или
поздно утечёт.

`SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` подставляет сам Supabase, их
заводить не нужно.

## Как развернуть заново

Через панель Supabase: **Edge Functions → Deploy a new function**, имя папки в
имя функции, содержимое `index.ts` — в поле кода. Проверка входящего ключа
(`Verify JWT`) должна быть **включена** у всех трёх.

После этого проверить секреты в **Edge Functions → Secrets** — без них функции
отвечают «not_configured» и писем не шлют.
