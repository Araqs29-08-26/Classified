## Как мы теперь работаем

| Кто | Что делает |
|---|---|
| **Вахагн + Cowork (эта среда)** | Ставим задачи, принимаем решения, придумываем и сверяем стратегию, проверяем результат, ведём документы и память проекта |
| **Claude Code** | Пишет код, меняет настройки, деплоит, чинит сборку — всё, что руками в репозитории |

Почему так: запись в GitHub из Cowork заблокирована самой средой (проверено
дважды, ошибка «репозиторий не входит в разрешённый для сессии список»,
и это не зависит от токена). В Claude Code GitHub подключается штатно.
А без хранилища кода любая мелкая правка превращается в пересборку сайта
заново — именно это трижды провалилось 05–06.09.2026.

**Правило приёмки:** ни одна задача не считается сделанной, пока не выполнено
`npm run build` без ошибок И страница не открыта на preview-адресе и проверена
глазами. Формулировка «сделано, но не проверено» не принимается.

**Правило размера:** одна задача = одно изменение. Никаких пакетов из нескольких
несвязанных правок в одном заходе.

## Мелочи, найденные при восстановлении (чинить попутно)

- **Цена всегда форматируется по-русски.** `formatPrice` в `src/lib/supabase.ts`
  зашит на локаль `ru-RU` независимо от выбранного языка интерфейса.
- **Объяснения «Почему» на странице оценки — только по-русски.** Они
  захардкожены в коде и не проходят через словари, поэтому на `/hy` и `/en`
  остаются русскими. При переходе на движок это надо решить сразу:
  названия статусов, узоры и пояснения движка тоже пока только на русском —
  армянский и английский варианты ещё не составлены.
- **Фильтры не попадают в адресную строку.** Адрес → фильтры работает,
  обратно нет: отфильтрованную выдачу нельзя послать ссылкой, при перезагрузке
  фильтры сбрасываются.
- **Счётчики у операторов не учитывают фильтры** — цифры 0 / 2 / 0 не меняются
  при выборе.
- **`sell.result.priceLabel`** есть в словарях, но не используется: над ценой
  печатается `tierLabel`. Похоже, два ключа перепутаны местами.
- **`home.stats` без формы множественного числа** — по-английски выходит
  «Showing 1 listings».
- **Ключи `home.filters.apply / allOperators / allTiers / allTypes`** остались
  от прежней версии фильтров и нигде не используются.

## Отдельно: найденная ошибка в «Движке оценки номеров» (не задача сайта)

Автотест 15 эталонных случаев проходит **15 из 15**, срок владения работает
правильно (077 24 44 44 → 500 ֏ при 40 месяцах и 1 100 500 ֏ при 5 месяцах).

Но проверка из пакета передачи «номер с подменой цифр буквами
(`О9I 11 11 O1`) должен разбираться» **не проходит**:

- ожидалось: Премиум, индекс 98 (как у `091 11 11 01`);
- получено: Платиновый, индекс 65.

Причина найдена. В `araqs-number-engine.js`, строка 79, в таблице `HOMOGLYPHS`
есть кириллическая `І` (U+0406) и латинская `l`, но **нет латинской `I`
(U+0049)**. Поэтому `I` просто выбрасывается как «не цифра», строка
`О9I 11 11 O1` превращается в `09111101` — ровно 8 цифр, значит ветка
«срезать ведущий ноль» не срабатывает, и номер читается как код `09` + тело
`111101` вместо кода `91`.

Исправление на один символ — добавить `"I":"1","i":"1"` в `HOMOGLYPHS`.
Стоит заодно проверить и другие подмены (`|`, `S`→5, `B`→8).

Это задача проекта «Движок оценки номеров», не сайта. Пока движок в папке
сайта лежит **без изменений, версия 1.1** — как прислали.
